Lesson 01 · Foundations · The contract ships first

The Contract Is the Product

Assumption first: clients outlive every implementation behind them. Stripe processed $1.4 trillion without double charging anything because the API promise held while ledgers plus regions plus vendors moved underneath. Design the promise before the handler. Version the promise like money depends on it, because it does.

  • Name resources as nouns plus actions as verbs. Verbs in URLs age into lies the moment a second client arrives.
  • One contract, many handlers. Stripe plus Razorpay both kept promises while swapping queues plus regions underneath.
  • Deep dive: The Ledger That Cannot Blink, idempotency keys plus double-entry discipline at $1.4 trillion.

Lesson 02 · Evolution · Change without casualties

Version Without Breakage

Every breaking change is a migration you force on strangers. Salesforce once queued logins behind one shared path on conference day two, which is what a forced migration feels like at scale. Ship v2 beside v1. Measure adoption. Sunset with dates plus headers, never with surprises.

  • Prefer URL versions for public APIs plus header versions for partners who negotiate. Either works when the sunset date is contractual.
  • Emit Sunset plus Deprecation headers on every old response. Clients that can see the deadline meet the deadline.
  • Deep dive: The Login Queue That Ate Dreamforce, shared paths plus forced marches.

Lesson 03 · Safety · Retries that cannot double charge

Idempotency Keys End Double Charges

Networks retry. That is not a bug, that is physics. The bug is charging twice for one intent. Stripe solved it with idempotency keys plus a double-entry ledger, so a retried request replays the stored result instead of repeating the side effect. Every mutating endpoint needs the same discipline.

  • Keys ride in headers, never in bodies. The key identifies intent while the body carries details.
  • Store key plus response for at least 24 hours. A retry inside the window replays. Outside it starts fresh.
  • Deep dive: The Ledger That Cannot Blink, exactly the machinery, priced.

Lesson 04 · Capacity · Admission is a budget

Rate Limits Are Capacity

Azure West US taught the industry that retries multiply a 75 percent capacity loss into a 6 times overload at the surviving edge. Limits at the gateway turn that flood into a queue with fast errors instead of slow timeouts. Scale without limits replays the incident faster. Limits without scale prolongs the pain. Together they converge.

  • Gate per key plus per route plus per region. One bucket per dimension, each with its own refill math.
  • Return 429 with Retry-After plus a limit-policy header. Clients that can compute backoff will back off.
  • Deep dive: Azure West US Route Withdrawal, admission math at 1.4M offered RPS.

Lesson 05 · Contracts · Specs that generate trust

OpenAPI Turns Promises Into Artifacts

Thirteen thousand postings in ninety days ask for REST API skill, plus five thousand ask for OpenAPI by name. The spec is the contract clients code against, mocks run from, plus gateways enforce. A spec reviewed like code prevents the drift that becomes the midnight page.

  • Lint specs in CI: no verb URLs, no unpaged lists, no undocumented errors. Red spec blocks the merge.
  • Generate server stubs plus client SDKs plus mocks from one source. Three artifacts, zero drift.
  • Deep dive: Razorpay Kafka, what happens when client contracts meet partition limits.

Lesson 06 · Topology · Where the policy lives

Gateway Versus Mesh

A gateway enforces at the border. A mesh enforces between every pair of services. Use the gateway for client-facing policy such as auth plus limits plus versioning. Use the mesh for service-to-service policy such as mTLS plus per-route budgets. One border, many interiors. Confusing the two buys two bills plus one gap.

  • Terminate TLS plus validate auth plus apply limits at the gateway. Fail fast before interior spend.
  • Run mTLS plus retries plus timeouts in the mesh. Interior policy travels with the call, not the docs.
  • Deep dive: Cell-Based Control Planes, bulkheads that hold when maps fail.

Lesson 07 · Identity · Every call proves itself

Auth at the Edge

None of your handlers should parse credentials. The edge validates tokens, checks scopes, plus forwards identity downstream as headers services can trust. OAuth scopes carry permission. mTLS carries workload identity. IAM carries cloud permission. Mix them deliberately or attackers will mix them for you.

  • Validate plus cache JWKS with short TTLs. A slow validator becomes the outage, as us-west1 proved for IAM.
  • Scope per action, not per service. Broad scopes turn one leaked token into a skeleton key.
  • Deep dive: GCP us-west1, when IAM validation queues behind disk.

Lesson 08 · Async · Callbacks that survive the night

Webhooks at Scale

Stripe-scale webhooks mean millions of outbound callbacks into customer endpoints of unknown quality. Sign every payload. Retry with backoff plus jitter across hours. Keep per-destination queues so one slow customer cannot stall the rest. The callback is your API in reverse, with all the same discipline owed.

  • HMAC-sign payloads with rotating secrets plus versioned signatures. Unsigned callbacks are rumors.
  • Retry 8 times over 3 days with jitter. Dead-letter the rest to a dashboard someone actually reads.
  • Deep dive: The Ledger That Cannot Blink, webhook storms at 1M RPS.

Lesson 09 · Scale · Lists that do not fall over

Pagination Discipline

Offset pagination scans deeper with every page, which means page 10,000 costs a full table walk. Cursor pagination walks an index forward at constant cost. At Discord trillions-of-messages scale the difference is the cluster. Default to cursors. Reserve offsets for admin UIs with small result sets.

  • Encode cursor as opaque token with sort key plus tiebreaker. Clients iterate, never compute.
  • Cap page size plus enforce max window. A client asking for a million rows is asking for your outage.
  • Deep dive: Discord message storage, hot partitions plus quorum fan-in.

Lesson 10 · Clients · Failures they can act on

Errors Clients Can Handle

Every error must answer three questions: what happened, whether retry helps, plus what to do next. Machine-readable codes plus retryable flags plus request IDs turn a 3 AM mystery into a 3 PM ticket. Salesforce darkness taught that support goes dark with the product unless errors carry their own flashlight.

  • Mark every error retryable or terminal. Ambiguous errors breed the retry storms of Lesson 04.
  • Echo a request ID in every response plus every log line. Correlation without IDs is archaeology.
  • Deep dive: The Login Queue, darkness with no flashlight.

Lesson 11 · Economics · Retiring versions for profit

Deprecation Economics

Every live version bills forever: test matrices plus docs plus support plus incident surface. Deprecation converts that annuity into a project with a date. Announce early, header every response, offer a migration sandbox, then delete. Versions are inventory. Inventory rots.

  • Price each live version per quarter: CI minutes plus support tickets plus incident share. Publish the number internally.
  • Give migration sandboxes with diff tooling. The version that is easy to leave is the version clients actually leave.
  • Deep dive: Figma Multiplayer, per-document isolation as versioning discipline.

Lesson 12 · Money · The gateway invoice

The Gateway Bill

Assume 1M RPS through gateway plus auth plus limits at a modeled $0.0000012 per origin request. That is about $3,100 per day before data plus support. Token buckets that shed 65 percent of storm load save $70,000 per five-hour storm at that scale. Run the RPS Envelope calculator with your own numbers. The bill hides in the boundary. Here the boundary has a rate limit.

  • Model per-request cost as gateway plus auth plus origin. Three lines, no mysteries.
  • Hold headroom as insurance with a published price. Unpriced headroom gets cut the quarter before the storm.
  • Deep dive: Azure West US, the full invoice model.

Lesson 13 · Practice · Prove compatibility continuously

Breaking-Change Drills

Consumer-driven contracts flip testing: consumers publish what they need, providers verify every build against those pacts. A pact suite that runs per commit catches the renamed field before it ships. Pact tests are cheaper than apologies by roughly three orders of magnitude. Run them like billing depends on it.

  • Collect pacts from top consumers first. Ten pacts catch more breakage than ten thousand unit tests of shape.
  • Verify pacts in CI plus canary. A pact that only runs nightly is a history book.
  • Deep dive: Kafka Rebalance Explained, contract discipline under protocol change.

Lesson 15 · Capstone · One contract, three clients

Ship One API

Start small on purpose. One resource, three clients, one gateway. Write the OpenAPI spec, generate mocks, gate with buckets, sign webhooks, publish pacts, run a breaking-change drill, price the month. An API you have broken on purpose is the only kind you understand.

  • Run the fourteen drills from lessons 1 through 13 against one real contract. Gaps show at a glance.
  • Kill a version mid-week plus measure migration. Untested sunsets are rumors with headers.
  • Close with the invoice. Requests per month times modeled unit price, labeled as estimates.
